# Rust core and UniFFI

Verified 2026-09-19 against UniFFI 0.32.1. Pins in versions.md.

**Crate layout:** the samples below put UniFFI attributes directly on `core`, which is the simplest arrangement for a UniFFI-only project. Once the NAPI adapter exists, the correct topology is a pure `core` with no binding attributes plus one adapter crate per generator, using UniFFI's `#[uniffi::remote(...)]` for core types — see core-purity-and-io.md.

## Crate setup

```toml
[package]
name = "yourapp-core"
edition = "2021"
rust-version = "1.90"

[lib]
crate-type = ["cdylib", "staticlib"]   # staticlib is REQUIRED for iOS

[dependencies]
uniffi = { version = "=0.32.1", features = ["cli"] }

[build-dependencies]
uniffi = { version = "=0.32.1", features = ["build"] }
```

Omitting `staticlib` produces a crate that builds fine everywhere and then fails only when you try to link it into an iOS app. Add it up front.

At the top of `src/lib.rs`:

```rust
uniffi::setup_scaffolding!();
```

Never call both `setup_scaffolding!()` and `include_scaffolding!()` in the same crate.

## Use proc-macros, not UDL

Proc-macros are the recommended path. UniFFI's own docs call generating from a single UDL file "deprecated… we support it almost by accident for legacy reasons." Write `#[uniffi::export]` on functions, impl blocks, and traits; `#[derive(uniffi::Record)]` / `#[derive(uniffi::Enum)]` / `#[derive(uniffi::Object)]` on types.

Two proc-macro gotchas:

- **`#[cfg()]` does not work inside a `#[uniffi::export]` block.** Scaffolding is generated regardless and you get compile errors. Put `#[cfg()]` *outside*, using separate export blocks per platform.
- To make UniFFI optional behind a feature, use `#[cfg_attr(feature = "uniffi", uniffi::export)]`. This is worth doing — it keeps the door open for a second binding facade later without forking the core.

## The bindgen binary — build it in your workspace

This is the single most important structural decision. UniFFI's runtime version guard (`UNIFFI_CONTRACT_VERSION`) has been **frozen at 30 since v0.30.0**, spanning releases that made genuinely FFI-breaking changes. It will happily accept bindings generated by 0.31 against scaffolding built by 0.32, and you will get a confusing per-function checksum error at runtime instead of a clear version error.

Make the versions structurally identical by building the bindgen from the same lockfile:

```toml
# uniffi-bindgen/Cargo.toml
[dependencies]
uniffi = { version = "=0.32.1", features = ["cli"] }

[[bin]]
name = "uniffi-bindgen"
path = "src/main.rs"
```

```rust
// uniffi-bindgen/src/main.rs
fn main() {
    uniffi::uniffi_bindgen_main()
}
```

Then generate with `cargo run -p uniffi-bindgen -- generate ...`.

## Generating bindings

Pass the **compiled library path** directly. Do not pass a UDL file, and do not use `--library`:

```bash
cargo build --release
cargo run -p uniffi-bindgen -- generate \
    target/release/libyourapp_core.so \
    --language kotlin --out-dir android/src/main/java
```

- **`--library` is deprecated and has no effect** since UniFFI 0.31.0. The bindgen auto-detects library vs UDL by file extension.
- **`--lib-file` was removed** in 0.31.0.
- **`--config` changed meaning in 0.32.0.** It now expects a *global* config file, not a flat `uniffi.toml` override. Old-style files "produce a warning and be ignored" — a silent misconfiguration.
- Library mode must run from inside the project's cargo workspace.

For Swift, prefer the dedicated `uniffi-bindgen-swift` binary — see apple-swift.md.

## Async

Async functions work and map to native foreign async: `suspend fun` in Kotlin, `async`/`await` in Swift. The foreign side supplies the executor; you do not need a Rust event loop.

```rust
#[uniffi::export]
pub async fn fetch_summary(id: String) -> Result<Summary, CoreError> { ... }
```

For async trait methods, put `#[uniffi::export]` **outside** `#[async_trait::async_trait]`:

```rust
#[uniffi::export]
#[async_trait::async_trait]
pub trait Loader: Send + Sync {
    async fn load(&self, key: String) -> Result<Vec<u8>, CoreError>;
}
```

If the core uses Tokio, add `#[uniffi::export(async_runtime = "tokio")]`. As of 0.32.0 this also works on trait exports.

**Async primary constructors are a hard error** in Kotlin and Python as of 0.32.0. Use a named async factory function instead of an async `new`.

## Cancellation does not exist

UniFFI's docs: "We don't directly support cancellation in UniFFI even when the underlying platforms do… There's no builtin way to cancel a future, nor to cause/raise a platform native async cancellation error."

The required pattern:

```rust
#[uniffi::export]
impl Job {
    pub fn cancel(&self) { self.cancelled.store(true, Ordering::Relaxed); }
}
```

The core checks the flag at await points and returns `Err(CoreError::Cancelled)`. Do not tell host developers that Swift task cancellation or coroutine cancellation will propagate — it will not.

## Errors

Define one error enum and derive it:

```rust
#[derive(Debug, thiserror::Error, uniffi::Error)]
pub enum CoreError {
    #[error("not found: {id}")]
    NotFound { id: String },
    #[error("invalid input: {reason}")]
    Invalid { reason: String },
    #[error("cancelled")]
    Cancelled,
}
```

Enums and records can export `Display`, `Debug`, `Eq`, `Hash`, and `Ord`, which surface in Kotlin as `toString()`, `equals()`, `hashCode()`, and `compareTo()`. **Flat enums only support `Display`.** Custom `enum` and `object` types are usable as error types.

## Custom types

`UniffiCustomTypeConverter` was **removed in 0.29**. Use the macro:

```rust
uniffi::custom_type!(UserId, String, {
    try_lift: |s| Ok(UserId(s)),
    lower: |v| v.0,
});
```

The closures can be omitted where `From`/`Into` already exist. `uniffi::custom_newtype!` is the shorthand for newtype wrappers.

## Useful recent capabilities

- **Recursive enums** work as of 0.32.0 — self-referential, mutually recursive, or cycling through a record. Generates `indirect` in Swift. Useful for nested command or event types.
- **`Box<T>`** auto-implements the FFI traits when `T` does, so no newtype wrapper is needed in enum variants.
- **Records and enums can have methods** as of 0.31.0, which keeps a pure-core design ergonomic.
- **Renaming**: `#[uniffi::export(name = "...")]` works on types, methods, record fields, and enum variants, and TOML-based renaming covers most of the interface.

## Things that changed and will break copied code

| Pattern | Status | Replacement |
|---|---|---|
| `#[uniffi::export(with_foreign)]` | Deprecated in 0.32.0 | `#[uniffi::export(rust, foreign)]` or `(foreign)` |
| `--library` flag | Inert since 0.31.0 | Omit; auto-detected |
| `--lib-file` flag | Removed in 0.31.0 | Pass the library path directly |
| `UniffiCustomTypeConverter` | Removed in 0.29 | `uniffi::custom_type!` |
| `typedef extern Foo` in UDL | Removed in 0.29 | Name the kind: `typedef enum Foo` |
| `NoPointer` (Kotlin) | Renamed in 0.30.0 | `NoHandle` |
| UDL trait interfaces | 0.30.0 requires a wrapper | `#[uniffi::trait_interface]` |
| `[ByRef] bytes` → `&Vec<u8>` | Changed in 0.32.0 | Now `&[u8]`; Kotlin call sites must pass a **direct** `ByteBuffer` |
| `FfiType::RustArcPtr` | Removed in 0.30.0 | Objects cross the FFI as `u64` handles |
